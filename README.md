# train-route — 환승 열차 탐색

출발 시각 기준으로 직통·환승 1~2회 조합을 전부 펼쳐 **실제로 가장 빨리 도착하는 열차 조합**을 찾아주는 웹앱.
출발·도착역을 여러 개 고를 수 있고, "인접역 포함"을 켜면 가까운 역(예: 천안·천안아산·아산)을 함께 찾는다.

## 준비
1. https://www.data.go.kr/data/15098552/openapi.do 에서 **활용신청** (개발계정 자동승인, 하루 10,000건)
2. 마이페이지에서 **일반 인증키(Decoding)** 복사
3. `.env.example` → `.env` 로 복사 후 `TAGO_KEY=` 뒤에 붙여넣기

## 실행 (Node 22+, 설치할 패키지 없음)
```
npm run local
```
→ http://localhost:8787

인증키는 서버에만 있고 브라우저로 나가지 않는다.

테스트(API 호출 없음): `npm test`

## 배포 (Vercel)
- 주소는 `app.ktkring.com/train/`. 관문 프로젝트 `ktk-ring/app`이 이 프로젝트(`train-route-pi.vercel.app`)로 rewrite한다.
- Vercel에서 이 저장소를 Import → Environment Variables에 `TAGO_KEY` → Deploy. 빌드 단계는 없고 `public/`과 `api/` 함수가 배포된다(리전 `icn1`, `vercel.json`).
- 화면은 API를 상대 경로로 부른다. 그래서 루트(`/`)와 `/train/` 아래 모두에서 같은 코드로 동작한다.
- 역 목록은 `data/stations.js` 스냅샷을 쓴다. 역이 바뀌면 `npm run stations`로 갱신해서 커밋한다.

## 동작 방식
- TAGO API는 "A역→B역" 구간 단위로만 열차를 준다 → 출발역·환승 후보역·도착역 사이 구간 시간표를 모아 이어붙임
- 구간마다 "탈 수 있는 열차 중 가장 일찍 도착하는 열차"를 선택, 최소 환승 여유 시간 적용
- 환승 2회는 방향이 맞고 너무 돌아가지 않는 허브 쌍만 조회(조회 수 약 절반, 결과는 같음)
- **연계 링크**: 천안아산↔아산(도보), 천안아산↔천안(1호선), 대전↔서대전(대전 1호선), 부산↔부전(부산 1호선) 등 TAGO에 없는 이동을 이어 줌. 시간표가 없어 대기를 배차 간격만큼(최악)으로 잡고 도착을 "늦어도"로 표시(`lib/links.js`)
- 결과는 "더 늦게 출발 / 더 일찍 도착 / 환승이 적음" 중 하나라도 나은 경로만 남김(파레토)
- 구간 시간표는 날짜별로 6시간 캐시(로컬 `cache/`, Vercel은 인스턴스 `/tmp`), 같은 조건의 경로 응답은 CDN이 30분 캐시
- TAGO 초당 한도(약 30~50건, 넘으면 30초 차단)를 지키려고 초당 20건 이하로 보냄. 못 불러온 구간이 있으면 화면에 알림

## 알려진 한계
- 환승 후보역(허브) 목록 밖의 역에서 갈아타는 경로는 못 찾음 → 화면의 "환승 후보역 편집"에서 추가
- 환승 2회 첫 조회는 구간 100여 개를 불러서 몇 초 걸릴 수 있음(같은 날 재조회는 캐시)
- 연계 링크의 소요·배차는 대략치(실제 시간표 아님)
- 잔여 좌석은 알 수 없음(공식 API 없음), SRT 포함 여부는 TAGO 데이터에 따름
